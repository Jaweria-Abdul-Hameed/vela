# F03: Test kit foundation: fixture repositories, fakes, and fault points

**Planned labels:** `type:test` `area:foundation` `risk:medium` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 2 · **Direct blockers (published, transitively reduced):** F02

> Symbolic key: `F03` · Area: foundation · Phase: 0 · Risk: medium

## 2. Objective
Tests can build realistic throwaway Git repositories outside synced folders, use fake ports, and inject faults at named points.

## 3. Requirement IDs
NFR Testability, AT-001, AT-005

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- FixtureRepo builder producing temp repositories (multi-package project, seeded tickets, seeded review defect, schema-overlap pair, merge-conflict pair, hostile local-config repository).
- Fake implementations of each port (deterministic, scriptable) with recorded-transcript replay support.
- FaultPoint enum compiled under a test feature with a kill-at-point mechanism used by recovery tests.
- Guard that refuses to create fixtures under OneDrive or other synced folders.

## 6. Architectural constraints
- Cargo workspace plus npm workspaces only (ADR-017); no additional monorepo orchestration.
- Crate dependency direction is enforced in CI (IMPLEMENTATION_ARCHITECTURE.md section 3).

## 7. Dependencies / blocked by
- F02 Domain primitives, ports, and TypeScript contract generation

## 8. Expected write surfaces
- crates/vela-testkit/**
- tests/fixtures/**

## 9. Known shared contracts
- Cargo.toml and package.json at the root (serialization hazard)
- Workspace layout in docs/architecture/DIRECTORY_STRUCTURE.md
- FixtureRepo API and FaultPoint names (used by many later tests)

## 10. Parallelization notes
Parallel with F04 and F06 after F02 (disjoint crates). Later tests extend fixtures additively; coordinate on the shared FixtureRepo builder.
