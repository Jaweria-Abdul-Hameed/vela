# F03: Test kit foundation: fixture repositories, fault-injection harness, and the synced-folder guard

**Planned labels:** `type:test` `area:foundation` `risk:medium` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 2 · **Direct blockers (published, transitively reduced):** F02

> Symbolic key: `F03` · Area: foundation · Phase: 0 · Risk: medium

## 2. Objective
Tests can build realistic throwaway Git repositories outside synced folders and can kill and restart a process at named fault points.

## 3. Requirement IDs
NFR Testability, AT-005

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- FixtureRepo builder producing temp repositories outside synced folders: multi-package project, seeded tickets, seeded review defect, schema-overlap pair, merge-conflict pair, and the hostile local-config repository.
- Kill-and-restart harness built on the F02 `fault-injection` feature: re-executes a test binary with a named fault point armed, then restarts it against the same state directory.
- Guard that refuses to create fixtures under OneDrive or other synced folders.

## 6. Architectural constraints
- Cargo workspace plus npm workspaces only (ADR-017); no additional monorepo orchestration.
- Crate dependency direction is enforced in CI (IMPLEMENTATION_ARCHITECTURE.md section 3).

## 7. Dependencies / blocked by
- F02 Domain primitives, ports, and TypeScript contract generation

## 8. Expected write surfaces
- crates/vela-testkit/src/fixture_repo/**
- crates/vela-testkit/src/fault_harness/**
- tests/fixtures/** (fixture specifications and Markdown issue sets; not transcripts)

## 9. Known shared contracts
- FixtureRepo API (used by many later tests)
- Fault harness API and the FaultPoint names declared by owning tickets

## 10. Parallelization notes
Parallel with F04 and F06 after F02 (disjoint crates and directories). F09 (port fakes and conformance) follows in the same crate. Later tests extend fixtures additively through new files, not by editing the builder core.

## 11. Acceptance criteria
- [ ] Each fixture repository kind is generated deterministically and verified by Git commands.
- [ ] The synced-folder guard rejects a OneDrive path in a test.
- [ ] The kill-and-restart harness arms a named point, kills the child, restarts it, and reports the state found, demonstrated on a sample state machine.

## 12. Required unit tests
- Fixture builder determinism tests; guard path-classification tests (OneDrive, Dropbox, Google Drive, iCloud patterns); harness arm/kill/restart self-test.

## 13. Required integration tests
- Each fixture repository kind is inspected with real Git commands (hostile repository really contains the neutralizable drivers and hooks).
