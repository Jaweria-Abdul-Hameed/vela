# X05: CI supply-chain gates: secret scanning, dependency audit, license check, and locked builds

**Planned labels:** `type:infra` `area:security` `risk:medium` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 1 · **Direct blockers (published, transitively reduced):** F01  
**Added by the Prompt 7 independent audit** (not in the Prompt 6 draft).

> Symbolic key: `X05` · Area: security · Phase: 0 · Risk: medium

## 2. Objective
Every push and pull request is scanned for secrets and vulnerable or disallowed dependencies, and lockfile drift fails CI, so the release checklist items for secret scanning and supply chain are enforced continuously.

## 3. Requirement IDs
NFR Security, FR-035

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Secret scanning of the pushed range with rules for credential-like files and patterns (`.env`, key and certificate files, Antigravity and `.gemini` credential paths, tokens).
- Rust advisory, license, ban, and source checks (for example cargo-deny) and `npm audit --omit=dev`; high severity fails unless an allowlist entry with a justification and an expiry exists.
- Lockfile drift check (`--locked` builds and `npm ci`), and a software bill of materials artifact for release builds.

## 6. Architectural constraints
- Secrets never reach the repository, logs, the journal, or diagnostics (ADR-013).
- Gate configuration is data in the repository; a gate cannot be disabled by editing a ticket, an issue, or AGENTS.md text.

## 11. Acceptance criteria
- [ ] A seeded fake secret in a test branch fails the scan; a clean branch passes.
- [ ] A seeded disallowed license or vulnerable dependency fails the check unless allowlisted with a justification and an expiry.
- [ ] Lockfile drift fails CI.
- [ ] A software bill of materials is produced for a release-profile build.

## 12. Required unit tests
