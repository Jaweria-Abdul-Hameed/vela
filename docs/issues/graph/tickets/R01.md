# R01: Operation records and idempotency framework

**Planned labels:** `type:feature` `area:recovery` `risk:high` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 6 · **Direct blockers (published, transitively reduced):** O01

> Symbolic key: `R01` · Area: recovery · Phase: 3 · Risk: high

## 2. Objective
Every external operation has an id, persisted intent, observed result, and a reconciliation recipe.

## 3. Requirement IDs
FR-019, FR-022

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- operations table usage; intent-before and result-after helpers; per-operation recipe registry framework (the operation-owning tickets register their own recipes: checkpoint, merge, push, approval; the framework ships with the checkpoint-by-trailer recipe using the commit conventions).

## 6. Architectural constraints
- Persist intent before every non-idempotent external action and the observed result after; never guess after divergence.
- Never replay a stale UI click.

## 7. Dependencies / blocked by
- O01 Orchestrator actor skeleton: message bus, transactional transitions, run creation, snapshot assembly
