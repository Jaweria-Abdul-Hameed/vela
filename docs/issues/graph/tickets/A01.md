# A01: Antigravity capability discovery: installation, versions, flags, and authentication state

**Planned labels:** `type:feature` `area:antigravity` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 4 · **Direct blockers (published, transitively reduced):** P01, F03

> Symbolic key: `A01` · Area: antigravity · Phase: 1 · Risk: high

## 2. Objective
Preflight can tell whether the official agy is installed, its version and flags, the Desktop version, and whether the user is authenticated, using only supported interfaces.

## 3. Requirement IDs
FR-037, FR-049, FR-002, AT-025

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Detect agy (path, version, help-derived flag set), Desktop installation and version, CAP-01..CAP-12 report with required/optional classes and the BLOCK or degradation outcome; authentication state through Antigravity own interfaces; AUTH_REQUIRED and CAPABILITY_MISSING errors.

## 6. Architectural constraints
- Only vela-adapters::antigravity and vela-uia may contain Antigravity-specific behavior (ADR-008, ADR-018).
- Never trust exit code or result.status; interpret events, stderr, and Git state.
- Never read, copy, or persist Antigravity credentials or tokens (ADR-016).
- Elements tagged [U] are gated by their spike; do not claim them ready.

- P01 ProcessRunner: spawn, allowlisted environment, timeouts, streamed redacted output, cancel token
- F03 Test kit foundation: fixture repositories, fakes, and fault points
