# P02: Process tree kill and cancellation

**Planned labels:** `type:feature` `area:process` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 4 · **Direct blockers (published, transitively reduced):** P01, SP03

> Symbolic key: `P02` · Area: process · Phase: 1 · Risk: high

## 2. Objective
Every spawned tree can be cancelled gracefully then forced with no orphans.

## 3. Requirement IDs
FR-021, FR-009

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Job Object (or the verified fallback from the spike) for every spawned tree; graceful request then forced termination after the configured wait; tracking registry for reconciliation.

## 6. Architectural constraints
- Windows-aware; process trees are tracked so cancellation and reconciliation find every child.
- All captured output passes through the central redaction layer.

## 7. Dependencies / blocked by
- P01 ProcessRunner: spawn, allowlisted environment, timeouts, streamed redacted output, cancel token
- SP03 Spike S-PROC-JOB: does a Windows Job Object with kill-on-close terminate a whole agy process tree?
