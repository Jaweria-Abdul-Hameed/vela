> Symbolic key: `F09` · Area: foundation · Phase: 0 · Risk: medium

## 2. Objective
Every port has a deterministic, scriptable fake that passes a shared conformance suite, so orchestration tests run without real tools.

## 3. Requirement IDs
NFR Testability, NFR Provider independence

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Fake implementations of every port (ProcessRunner, GitAdapter capabilities, IssueTrackerAdapter, Notifier, ApprovalSource, ApprovalDeliveryAdapter, PowerManager, SessionProbe, Clock, IdGenerator, AgentAdapter): deterministic, scriptable, and recording their calls.
- A provider-neutral scripted agent that emits normalized agent events from a scenario (success, failing tests, failure, timeout, ambiguity, capacity, provider policy block) and can replay recorded transcripts through the parser added by A02.
- A shared conformance suite that runs each fake against the port contract.

## 6. Architectural constraints
- vela-testkit is dev-only and depends on ports only (IMPLEMENTATION_ARCHITECTURE.md section 3).
- Fakes never touch the network, the user home directory, or credentials.
- The Antigravity-specific fake executable is TK1; this scripted agent is provider-neutral.

## 7. Dependencies / blocked by
- F03 Test kit foundation: fixture repositories, fault-injection harness, and the synced-folder guard

## 8. Expected write surfaces

## 9. Known shared contracts

- Scripted agent scenario API
