# S03: Repository trust: untrusted by default, trust sheet, data-only analysis, Build refusal

**Planned labels:** `type:feature` `area:security` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 6 · **Direct blockers (published, transitively reduced):** S01, G01, D05, S02

> Symbolic key: `S03` · Area: security · Phase: 1 · Risk: high

## 2. Objective
A newly imported repository is untrusted: Vela analyzes it as data only and refuses to Build until the user explicitly trusts it.

## 3. Requirement IDs
FR-043, AT-020

## 4. User-visible behavior
A trust sheet listing what becomes executable, the confirmed command profile, and Trust / Not now; trust can be revoked.

## 5. Technical scope
- Trust state and consent record persisted and journaled; hardened Git for untrusted repositories; Build and provisioning refused while untrusted; command profile capture; revocation.

## 6. Architectural constraints
- Repository, issue, and AGENTS.md text never changes policy, trust, or approval classification (ADR-013).
- Secrets never reach logs, the journal, or diagnostics.

## 7. Dependencies / blocked by
- S01 Project import: choose a repository, persist it, and list recent projects
- G01 GitAdapter: hardened invocation, read operations, and hostile-config tests
- D05 Policy engine core: operation model, PowerShell and cmd normalizer, ordered rules, ALLOW/ASK/DENY
- S02 Settings layers, onboarding choices, and the immutable run snapshot
