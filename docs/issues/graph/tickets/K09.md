# K09: Scoped rule creation from an intervention with the scope shown first

**Planned labels:** `type:feature` `area:broker` `risk:medium` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 8 · **Direct blockers (published, transitively reduced):** K01, U10

> Symbolic key: `K09` · Area: broker · Phase: 3 · Risk: medium

## 2. Objective
A user can create an explicit scoped allow rule from an intervention after seeing its exact scope; allow-once never creates a permanent rule.

## 3. Requirement IDs
FR-031

## 4. User-visible behavior
Rule editor in the intervention sheet showing scope, expiry, and consequences before saving.

## 5. Technical scope
- Rule creation and persistence; scope display; revocation; policy conflict check.

## 6. Architectural constraints

- Vela approves operations, not buttons; fail closed on any ambiguity.
- UI automation is opt-in and consent-gated (ADR-010).
