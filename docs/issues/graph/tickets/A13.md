# A13: Capacity detection from Antigravity output and pause/cooldown mapping

**Planned labels:** `type:feature` `area:antigravity` `risk:medium` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 13 · **Direct blockers (published, transitively reduced):** A03, S16

> Symbolic key: `A13` · Area: antigravity · Phase: 2 · Risk: medium

## 2. Objective
Quota exhaustion is recognized from the output and mapped to profile cooldown and worker pause without trusting exit codes. Antigravity evidence that the account or service is blocked for terms or policy reasons is mapped conservatively into the provider-neutral `ProviderPolicyBlock` event, and anything unclassifiable is never retried.

## 3. Requirement IDs
FR-024, AT-007

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- RESOURCE_EXHAUSTED text detection and reset-time parsing; mapping into the capacity model; explicit timeouts; headless retry-loop avoidance.
- Provider-policy-block mapping (in `capacity/policy_block.rs`; CAPACITY_AND_PROFILES.md "Provider Policy Blocks"): map only documented or recorded Antigravity signals (the official changelog records a distinct sign-in error with an appeal link for accounts blocked for a Terms violation, docs/research/H01_google_position.md) into the neutral `ProviderPolicyBlock` event, with the evidence excerpt redacted. Detection is `[U]`: do not hard-code speculative error strings, keep the signal table small and data-driven so recorded evidence can extend it, and never present the mapping as verified.
- Fail-safe classification: an access failure that cannot be classified as a policy block, a capacity limit, or a missing sign-in is surfaced with its evidence as `AUTH_REQUIRED` or `NEEDS_HUMAN` kind `OTHER`; it is never retried automatically and never switches profile, rotates credentials, or falls back to an API key. Never provoke a block to obtain evidence; any real occurrence is recorded in docs/research/ and the table updated.

## 11. Acceptance criteria
- [ ] Recorded quota transcripts pause only the affected worker with the reset time parsed when present.
- [ ] Exit code 0 is never treated as success when quota text is present.
