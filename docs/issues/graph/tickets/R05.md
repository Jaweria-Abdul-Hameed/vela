# R05: State-store failure: backup, failed migration, and Git-derived inventory rebuild

**Planned labels:** `type:feature` `area:recovery` `risk:high` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 6 · **Direct blockers (published, transitively reduced):** F06, G02, G03

> Symbolic key: `R05` · Area: recovery · Phase: 3 · Risk: high

## 2. Objective
A corrupt or missing store restores from backup or produces a read-only inventory with affected runs in NEEDS_HUMAN.

## 3. Requirement IDs
FR-046, AT-022

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Integrity check at start; backup rotation; failed-migration restore; inventory rebuild from vela branches, worktrees, and trailers; never auto-resume reconstructed state.

## 6. Architectural constraints
- Persist intent before every non-idempotent external action and the observed result after; never guess after divergence.
- Never replay a stale UI click.

## 7. Dependencies / blocked by
- F06 Persistence foundation: single-writer SQLite, migration ladder, journal, and integrity checks
- G02 Worktree manager: root policy, create, remove, lock, repair, slug and case safety, cleanup
- G03 Checkpoint commits, per-worktree operation lock, and hook-aware commit handling
