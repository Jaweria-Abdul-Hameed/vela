# K02: Approval Watchdog and loop guard: progress heartbeats, thresholds, APPROVAL_STALLED

**Planned labels:** `type:feature` `area:broker` `risk:high` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 8 · **Direct blockers (published, transitively reduced):** K01

> Symbolic key: `K02` · Area: broker · Phase: 2 · Risk: high

## 2. Objective
Blocked workers are detected from lack of progress and repeated equivalent approvals stop at a bounded threshold.

## 3. Requirement IDs
FR-032, FR-034, AT-013

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Heartbeats from journal events; state-aware thresholds (default 120 s, suppressed while a tracked command runs); fingerprint counters persisted per worker; APPROVAL_STALLED; suspected-block reporting when UI sources are unavailable.

## 6. Architectural constraints
- Policy and delivery are separate; no adapter decides safety (ADR-007).
- Vela approves operations, not buttons; fail closed on any ambiguity.
- UI automation is opt-in and consent-gated (ADR-010).

## 7. Dependencies / blocked by
- K01 Approval Broker core: classification pipeline, evidence tiers, decisions, rules, interventions

## 8. Expected write surfaces

## 9. Known shared contracts

- approval tables (requests, decisions, delivery attempts, fingerprints, policy rules)
