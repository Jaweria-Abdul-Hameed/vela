# K06: vela-uia delivery: single-use allow or refusal through patterns, never persistent options

**Planned labels:** `type:feature` `area:broker` `risk:high` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 6 · **Direct blockers (published, transitively reduced):** K05, S02

> Symbolic key: `K06` · Area: broker · Phase: 2 · Risk: high

## 2. Objective
After classification Vela delivers exactly one single-use allow or a refusal through UI Automation patterns and verifies the outcome.

## 3. Requirement IDs
FR-033, AT-011

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Option selection by role and label; SelectionItem and Invoke patterns only; refusal of persistent options; verify the card clears and progress occurs; assert no persistent permission via before and after configuration hashes in tests; consent required.

## 6. Architectural constraints
- Policy and delivery are separate; no adapter decides safety (ADR-007).
- Vela approves operations, not buttons; fail closed on any ambiguity.
- UI automation is opt-in and consent-gated (ADR-010).

## 7. Dependencies / blocked by
- K05 vela-uia discovery and read: windows, warm-up, correlation, and card observation
- S02 Settings layers, onboarding choices, and the immutable run snapshot
