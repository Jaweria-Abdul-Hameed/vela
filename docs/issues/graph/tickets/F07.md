# F07: Structured logging, correlation ids, and the central redaction layer

**Planned labels:** `type:feature` `area:security` `risk:medium` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 2 · **Direct blockers (published, transitively reduced):** F02

> Symbolic key: `F07` · Area: security · Phase: 0 · Risk: medium

## 2. Objective
All logs, process output, and journal payloads carry correlation ids and pass through one redaction layer so secrets never persist.

## 3. Requirement IDs
NFR Observability, NFR Security, FR-035

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- tracing setup with JSON log files and size-capped rotation; correlation ids (run, ticket, worker, operation).
- Redactor for tokens, authorization headers, credential-like environment values, cookies, and known secret patterns, applied at ingestion points.
- Redaction corpus tests.
- The Redactor is exposed as an injectable trait object consumed by ProcessRunner (P01), the diagnostics bundle (X03), and the Orchestrator journal path (O01); F06 does not call it.

## 6. Architectural constraints
- Repository, issue, and AGENTS.md text never changes policy, trust, or approval classification (ADR-013).
- Secrets never reach logs, the journal, or diagnostics.
