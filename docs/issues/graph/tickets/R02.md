# R02: Startup reconciliation and recovery-resume

**Planned labels:** `type:feature` `area:recovery` `risk:high` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 11 · **Direct blockers (published, transitively reduced):** S10

> Symbolic key: `R02` · Area: recovery · Phase: 3 · Risk: high

## 2. Objective
After a crash or restart Vela reconciles persisted state with refs, worktrees, and processes, classifies discrepancies, and resumes only safe idempotent steps.

## 3. Requirement IDs
FR-019, FR-022, AT-005

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Reconciliation engine; discrepancy classes; recovery-resume (new session at the last checkpoint); never guess after divergence.
- Recovery-resume consults the profile-availability service from the Orchestrator service registry (absent means available, until S16 registers one) and never starts a session on a profile reported as blocked (for example `POLICY_BLOCKED`, a provider policy block, CAPACITY_AND_PROFILES.md); reconciliation restores persisted intervention and block state as recorded and never clears or retries it.

## 6. Architectural constraints
- Persist intent before every non-idempotent external action and the observed result after; never guess after divergence.
- Never replay a stale UI click.

## 11. Acceptance criteria

- [ ] Recovery-resume refuses to start a session on a profile the availability service (a fake here) reports as blocked.
- [ ] Recovery-resume starts a new session on the existing branch and worktree at the last verified checkpoint with a recovery envelope.
