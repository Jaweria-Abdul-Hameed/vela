# D05: Policy engine core: operation model, PowerShell and cmd normalizer, ordered rules, ALLOW/ASK/DENY

**Planned labels:** `type:feature` `area:security` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 2 · **Direct blockers (published, transitively reduced):** F02

> Symbolic key: `D05` · Area: security · Phase: 1 · Risk: high

## 2. Objective
Every operation is classified by ordered, explainable rules with a small, safe normalizer; anything unparseable is ASK.

## 3. Requirement IDs
FR-030, FR-031, FR-038

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Operation and context model; normalizer for a single simple command in PowerShell and cmd syntax (no pipes, redirection, chaining, subexpressions, encoded commands, unresolved variables); default rule set from SECURITY_AND_PERMISSIONS.md; auto-allow only for confirmed command profile in trusted repos.
- Rule table generation types for the hook (hook-table feature) and allow-rule generation for the native settings.

## 6. Architectural constraints
- Repository, issue, and AGENTS.md text never changes policy, trust, or approval classification (ADR-013).
- Secrets never reach logs, the journal, or diagnostics.
