# F01: Workspace bootstrap: Cargo and npm workspaces, toolchain pins, CI checks

**Planned labels:** `type:infra` `area:foundation` `risk:low` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 0 · **Direct blockers (published, transitively reduced):** none

> Symbolic key: `F01` · Area: foundation · Phase: 0 · Risk: low

## 2. Objective
A fresh clone builds and tests an empty but correctly shaped workspace with one command each for Rust and TypeScript, and CI rejects forbidden crate dependencies.

## 3. Requirement IDs
NFR Maintainability, NFR Testability

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Create the Cargo workspace and npm workspaces with the frozen directory layout (empty crates and packages with placeholder tests).
- Pin Rust toolchain and Node/npm versions; formatting, lint, and typecheck commands for both languages.
- CI workflow running build, test, lint, typecheck, and the crate-dependency-direction check.
- .editorconfig, .gitattributes, .gitignore; document the dev commands in the repository README section.
- Declare, per crate and package, every third-party dependency and `windows` crate feature set that the frozen technology inventory assigns to it, with exact versions in `[workspace.dependencies]`; commit `Cargo.lock` and `package-lock.json` resolved for the whole inventory; builds use `--locked` and `npm ci` (SHARED_SURFACE_PROTOCOL.md section 2).
- Create every workspace member in the frozen layout as an empty member, including `tests/integration`, `tests/e2e`, `tests/antigravity-compat`, and `tools/fake-approval-window`, so no later ticket edits the root `members` list.
- Declare the module skeleton of every crate and package as empty modules in `lib.rs` (the table in SHARED_SURFACE_PROTOCOL.md section 1), so parallel tickets add files inside their own module and never edit a shared declaration list.

## 6. Architectural constraints
- Cargo workspace plus npm workspaces only (ADR-017); no additional monorepo orchestration.
- Crate dependency direction is enforced in CI (IMPLEMENTATION_ARCHITECTURE.md section 3).

## 10. Parallelization notes
First ticket; everything depends on it. Single owner of the root manifests, the lockfiles, and the crate module skeletons. Later tickets edit only their own crate manifest and their own module; a new third-party dependency follows the dependency-request rule (SHARED_SURFACE_PROTOCOL.md section 2).

## 11. Acceptance criteria
- [ ] cargo build and cargo test succeed on the empty workspace; npm install, typecheck, lint, and test succeed.
- [ ] A deliberately illegal dependency (for example vela-core depending on vela-git) fails the CI dependency check, shown in the test evidence.
- [ ] Directory layout matches docs/architecture/DIRECTORY_STRUCTURE.md; no speculative provider crates exist.
- [ ] All tool versions are pinned and documented; dev commands are listed.
- [ ] Every crate declares exactly the module skeleton in SHARED_SURFACE_PROTOCOL.md; a check fails when a skeleton module is missing.
- [ ] `cargo build --locked` and `npm ci` succeed from the committed lockfiles, which contain the full pinned inventory.
