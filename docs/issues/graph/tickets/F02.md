# F02: Domain primitives, ports, and TypeScript contract generation

**Planned labels:** `type:feature` `area:domain` `risk:medium` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 1 · **Direct blockers (published, transitively reduced):** F01

> Symbolic key: `F02` · Area: domain · Phase: 0 · Risk: medium

## 2. Objective
vela-domain defines the identifiers, value objects, error classes, and every port trait, and the TypeScript contract package is generated from them with a contract test scaffold.

## 3. Requirement IDs
NFR Provider independence, NFR Testability, FR-029

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Value objects (RunId, TicketId, WorkerId, CommitSha, BranchName, WorktreePath, GateResult, ReviewSeverity, DependencyEdge, RiskClass).
- All ports in IMPLEMENTATION_ARCHITECTURE.md section 3 as traits with typed errors (ERROR_HANDLING.md classes).
- EventEnvelope and the closed event-kind vocabulary; ts-rs derivations exporting to packages/contracts/src/generated.
- Command-registry type and a contract test that fails when a Rust command lacks a TypeScript wrapper or vice versa (scaffold; real commands arrive later).

## 6. Architectural constraints
- vela-domain depends on no other Vela crate and has no I/O (pure logic).
- Provider-specific concepts do not leak into domain types (ADR-006).

## 7. Dependencies / blocked by
- F01 Workspace bootstrap: Cargo and npm workspaces, toolchain pins, CI checks

## 8. Expected write surfaces
- crates/vela-domain/src/**
- packages/contracts/src/**

## 9. Known shared contracts
- vela-domain::ports traits
- ts-rs exported DTOs in packages/contracts
- EventEnvelope and journal event kinds
- Every port trait (central shared contract: later tickets must not change signatures without coordination)

## 10. Parallelization notes
Blocks nearly everything. Do not run other domain tickets concurrently with the port definitions; after it merges, domain tickets are largely independent.

## 11. Acceptance criteria
- [ ] All ports and value objects compile with documentation; ts-rs export runs under cargo test and produces TypeScript that typechecks.
- [ ] The event vocabulary matches SYSTEM_ARCHITECTURE.md section 4 exactly (a test enumerates it).
- [ ] The contract test scaffold passes with an empty registry and fails with a seeded mismatch.

## 12. Required unit tests

## 13. Required integration tests
