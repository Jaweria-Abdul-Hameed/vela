# S12: Merge lane and integration validation: two parallel tickets merge, gate, frontier advances

**Planned labels:** `type:feature` `area:orchestration` `risk:high` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 12 · **Direct blockers (published, transitively reduced):** S11, G04

> Symbolic key: `S12` · Area: orchestration · Phase: 2 · Risk: high

## 2. Objective
Reviewed tickets merge through the deterministic lane with validation, discard on failure, and frontier recomputation.

## 3. Requirement IDs
FR-017, FR-018, AT-002, AT-018

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Lane lock and operation record; update-branch-by-merge; no-ff merge; integration validation; discard unpublished merge on failure and return to FIXING; integration_health transitions; push after validation.
- Registers the merge and push reconciliation recipes with the operation framework.
- Declares FaultPoints for each merge-lane step and the push; sized as the largest orchestration ticket: if a session approaches its context limit, split at "push after validation and recipe registration" as a follow-up ticket rather than weakening acceptance.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

- G04 Merge operations: integration merge into branch, no-ff merge, discard unpublished merge, conflict detection
