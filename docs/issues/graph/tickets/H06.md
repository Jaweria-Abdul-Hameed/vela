# H06: Decide whether v1 creates Desktop-hosted Antigravity sessions for approval delivery (UI Automation path scope)

## 2. Objective
A recorded decision states whether v1 creates Desktop-hosted Antigravity sessions so that a Desktop approval card exists for UI Automation to deliver to, which determines whether UI Automation approval delivery serves real runs or stays a consent-gated capability verified against the controlled fake approval window only. This is an approval-delivery decision and is independent of ADR-020 conversation visibility.

## 3. Requirement IDs
FR-033, FR-040, FR-041

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Present the SP09 (interactive trust) evidence, and any already-recorded approval evidence, with the consequences for K07, for the real-Desktop scope of AT-011 and AT-017 in Z04, and for the guarded-automation consent copy; the decision and any ADR-018 section 5 amendment are the user's.
- Provisional posture until this decision is recorded: headless or programmatic agy remains the primary orchestration path; the UI Automation approval adapter may be implemented and tested against the controlled fake approval window; the real-Desktop approval-delivery acceptance scope stays unresolved. This posture must not weaken, defer, or substitute for the ADR-020, FR-050, CAP-12, and AT-026 requirement that in-scope Antigravity conversations be discoverable and openable in Antigravity Desktop.

## 6. Architectural constraints
- This ticket needs a human action; an agent prepares options and records the result.
- Do not choose on the user's behalf; raise a decision request with alternatives and consequences.
- Separation from ADR-020: this ticket does not decide FR-050, CAP-12, or AT-026, does not reinterpret or reopen ADR-020 decision 1a, and does not change the requirement that substantive in-scope conversations be fresh where required and discoverable and openable in Antigravity Desktop. Desktop-visible or openable does not mean Desktop-created or Desktop-hosted.
- This ticket does not authorize Desktop GUI automation to create or host conversations. ADR-020 decision 2 remains authoritative: prefer supported programmatic or headless agy orchestration with the same conversation visible and openable in Desktop; GUI automation for conversation creation is a last resort that needs a separate explicit decision, and only if SP08 shows that no supported route can satisfy ADR-020.
