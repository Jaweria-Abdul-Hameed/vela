# S16: Execution profiles and capacity model with simulated capacity events

**Planned labels:** `type:feature` `area:orchestration` `risk:medium` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 12 · **Direct blockers (published, transitively reduced):** R02, SP11

> Symbolic key: `S16` · Area: orchestration · Phase: 2 · Risk: medium

## 2. Objective
Capacity interruptions pause only the affected work and resume through supported profile semantics. A provider policy block is non-retryable: it stops provider work safely, is surfaced as an intervention, survives restart, and never clears except by an explicit user decision (FR-024).

## 3. Requirement IDs
FR-024, AT-007

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Profile states AVAILABLE, BUSY, COOLDOWN, AUTH_REQUIRED, UNAVAILABLE, DISABLED; worker PAUSED with reason CAPACITY; backoff; unrelated workers continue; no account switching.
- Owns reserved migration block 0120-0129 (`execution_profiles`); resume uses the recovery-resume operation delivered by R02; the Antigravity concurrency ceiling (CAP-05) comes from SP11.
- Provider policy block (CAPACITY_AND_PROFILES.md "Provider Policy Blocks"): profile state `POLICY_BLOCKED` entered from any state on the neutral `ProviderPolicyBlock` event; no backoff, retry, profile or account switch, API-key fallback, or new conversation; in-flight provider work cancelled at the next safe point; worker `NEEDS_HUMAN` and, when no ticket can progress without the profile, run `NEEDS_HUMAN`, both kind `PROVIDER_POLICY_BLOCK` with `resume_state`, created through the S15 model; `ProviderPolicyBlockRecorded` written with the state in one transaction; persisted so restart and reconciliation restore it and start no agent work.
- Registers the profile-availability service in the Orchestrator service registry that S09 (scheduler) and R02 (recovery-resume) already consult, and registers the S15 resolution precondition for the kind: only an explicit user decision after one user-initiated access re-check through the existing capability and authentication-state interface clears the block (`ProviderPolicyBlockCleared`), after which the worker or run returns to `resume_state` through recovery-resume. No timer, restart, or successful call clears it.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

## 11. Acceptance criteria
- [ ] A simulated rate limit pauses only the affected worker and the other workers continue (AT-007).
- [ ] The paused worker resumes at a checkpoint boundary through recovery-resume.
- [ ] No account or profile switching occurs outside supported profile semantics.
- [ ] A simulated `PROVIDER_POLICY_BLOCK` makes the profile `POLICY_BLOCKED`: no retry, backoff, profile or account switch, API-key fallback, or new conversation occurs; in-flight provider work stops at a safe point; worker and run become `NEEDS_HUMAN` with kind `PROVIDER_POLICY_BLOCK`; branches, worktrees, checkpoints, and the last safe commit are preserved (AT-007).
- [ ] After a kill and restart, reconciliation, the scheduler (S09), and recovery-resume (R02) leave the block in place and start no agent work on the profile.
- [ ] Only an explicit user decision after a user-initiated access re-check clears the block; a failed re-check leaves it; clearing resumes at the recorded `resume_state` through recovery-resume.

## 12. Required unit tests
- Profile state transitions (AVAILABLE, BUSY, COOLDOWN, AUTH_REQUIRED, UNAVAILABLE, DISABLED, POLICY_BLOCKED); backoff schedule with a fake clock; a capacity event affects only the paused worker.
- POLICY_BLOCKED table: entered from every state; left only by the explicit clear; no transition table entry starts work, retries, or switches profile; a fake clock advancing never clears it.

## 13. Required integration tests

- Provider-policy-block scenario with the F09 scripted agent: stop at a safe point, intervention created, persisted across a kill and restart (fault-point harness), start and resume refused, re-check failure keeps the block, explicit clear resumes.
