# G05: Remote operations: fetch, non-force push, remote ref verification, idempotent push

**Planned labels:** `type:feature` `area:git` `risk:medium` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 5 · **Direct blockers (published, transitively reduced):** G01

> Symbolic key: `G05` · Area: git · Phase: 1 · Risk: medium

## 2. Objective
Vela pushes branches by itself without force and can tell whether a push already happened.

## 3. Requirement IDs
FR-016

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Fetch when policy permits; push of worker and integration branches; remote ref verification for idempotency; typed network and auth errors.
- Declares FaultPoints `git.push.before` and `git.push.after` (SHARED_SURFACE_PROTOCOL.md section 6).

## 6. Architectural constraints
- Shell out to the git binary under the verified hardened invocation (IMPLEMENTATION_ARCHITECTURE.md; no libgit2).
- Never force-push; never rebase pushed branches; never touch the primary checkout working tree, index, or branch (ADR-011).

## 7. Dependencies / blocked by
- G01 GitAdapter: hardened invocation, read operations, and hostile-config tests

## 8. Expected write surfaces
- crates/vela-git/src/remote/**

## 9. Known shared contracts
- GitAdapter remote capability trait (F02)
- Uses the G01 per-worktree operation lock

## 10. Parallelization notes
Parallel with G02.

## 11. Acceptance criteria
- [ ] A push that already happened is detected by remote ref verification and is not repeated.
- [ ] No force flag is ever passed (property test over the argument builder).
- [ ] Network, authentication, and non-fast-forward failures are distinct typed errors.

## 12. Required unit tests
- Push argument builder never emits force flags (property); remote ref classification (already pushed, diverged, missing); error mapping.

## 13. Required integration tests
- Tests against a local bare remote.
