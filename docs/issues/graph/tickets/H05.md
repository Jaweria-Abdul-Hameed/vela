## 5. Technical scope
- **Canonical route (decided):** a local Windows 11 virtual machine under **VMware Workstation Pro** on the development machine (REF-HW-1, Windows 11 Home, where Windows Sandbox and the Hyper-V role are not supported). VMware is Vela's selected environment, not the only technically valid hypervisor: VirtualBox remains a possible alternative, but part of its coexistence evidence was secondary and unverified. A spare physical Windows machine is optional supplementary validation, not a v1 prerequisite. See `docs/research/H05_clean_machine_2026-10-03.md`.
- **Guest OS (decided):** the official Microsoft Windows 11 Enterprise 90-day Evaluation, used as a disposable validation guest. It is an Enterprise guest, not Windows Home; it is time-limited; it does not establish a licensing route for permanent infrastructure; and testing on Windows Home or another edition must be added deliberately if release validation later requires it. When the evaluation lapses the guest is re-provisioned, never extended by unsupported means. Provision close to Z07 so the period is not spent before it is needed. No licensing right beyond Microsoft's own published terms is assumed.
- **Initial VM configuration (a configurable starting point, not a performance requirement):** 4 vCPU; roughly 4 to 6 GB guest RAM; a dynamically allocated virtual disk with headroom for Windows, snapshots, and the N-1 and N artifacts (research estimate 60 to 100 GB); virtual TPM 2.0 and Secure Boot enabled; no nested virtualization; no GPU passthrough. It is a quiet-machine workload on a 16 GB host: not run concurrently with heavy Antigravity worker activity, performance benchmarking (PF1), large WSL workloads, or other memory-heavy work. No host setting is changed (no Windows feature, BIOS or UEFI, VBS, Memory Integrity, Smart App Control, or WSL change).
- **States, created only when an acceptance scenario needs them:** **S0** pristine baseline (Windows guest; no Rust, Node, Git, Antigravity, or Vela; VMware guest tools recorded explicitly as part of the baseline; Windows build, edition, and security state recorded) used for clean install, first launch and missing-prerequisite behavior, development Authenticode verification, uninstall, and reboot, tray, auto-start, and notification validation; **S1** N-1 installed, derived from S0, for N-1 to N upgrade, state preservation, backup, migration, and rollback; **S2** runtime-prerequisite state, derived from S0, with Git installed for project-level smoke (Antigravity and account-dependent testing stays outside the pristine baseline and is introduced only where a test requires it).
- **WebView2:** the Evergreen runtime is included with Windows 11 and no supported removal procedure is established, so a WebView2-absent state is not a prerequisite. Do not remove it through unsupported means. If a genuinely absent state cannot be obtained by a supported method, the missing-runtime path is recorded as NOT VERIFIED, never as passed.
- **Smart App Control:** not mandated ON or OFF for the guest. Record the actual state with every relevant run. A security rejection of a development or self-signed artifact under an enforcing posture is expected evidence, not an application failure.
- **Artifact transfer:** build the artifact and its SHA-256 manifest outside the guest; transfer by a read-only virtual disk or ISO (or another documented isolated mechanism); verify SHA-256 in the guest with built-in Windows facilities; no permanent shared folders, drag-and-drop, or clipboard dependency on the pristine baseline; network off by default and enabled only for a scenario that needs it (for example the WebView2 bootstrapper download); revert to the appropriate snapshot after each scenario.
- Record the build, edition, evaluation expiry date, snapshot names, guest-tools list, security-feature state, the transfer and restore procedures, and the evidence listing in `docs/release/CLEAN_MACHINE.md` (no keys or credentials). Smart App Control was observed ON on the current development machine, where it may block unsigned or self-signed development artifacts; changing it is not a prerequisite for any Vela work.
