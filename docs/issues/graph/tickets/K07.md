# K07: Interactive-session degradation and reconciliation for UI-automation work

**Planned labels:** `type:feature` `area:broker` `risk:medium` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 12 · **Direct blockers (published, transitively reduced):** K06, P03, R02, K01

> Symbolic key: `K07` · Area: broker · Phase: 3 · Risk: medium

## 2. Objective
When the desktop is locked, disconnected, or secure, affected workers pause and reconcile when an interactive session returns.

## 3. Requirement IDs
FR-041, AT-017

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Session probe integration; INTERACTIVE_SESSION_UNAVAILABLE pause; unaffected workers continue; on return re-detect, re-verify correlation, re-evaluate policy; never replay a stale click.

## 6. Architectural constraints
- Policy and delivery are separate; no adapter decides safety (ADR-007).
- Vela approves operations, not buttons; fail closed on any ambiguity.
- UI automation is opt-in and consent-gated (ADR-010).

## 7. Dependencies / blocked by
- K06 vela-uia delivery: single-use allow or refusal through patterns, never persistent options
- P03 Keep-awake thread and interactive-session probe
- R02 Startup reconciliation and recovery-resume
- K01 Approval Broker core: classification pipeline, evidence tiers, decisions, rules, interventions
