# K07: Interactive-session degradation and reconciliation for UI-automation work

**Planned labels:** `type:feature` `area:broker` `risk:medium` `phase:3` `ready-for-agent`  
**Depth in the DAG:** 12 · **Direct blockers (published, transitively reduced):** K06, P03, R02, H06, K02

> Symbolic key: `K07` · Area: broker · Phase: 3 · Risk: medium

## 2. Objective
When the desktop is locked, disconnected, or secure, affected workers pause and reconcile when an interactive session returns.

## 3. Requirement IDs
FR-041, AT-017

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Session probe integration; INTERACTIVE_SESSION_UNAVAILABLE pause; unaffected workers continue; on return re-detect, re-verify correlation, re-evaluate policy; never replay a stale click.
- Owns `wiring/approval.rs`: constructs the UI Automation source and delivery only when consent is on and the capability probe passes, and wires the broker (K01), the watchdog (K02), and the session probe (P03) into the composition root.

## 6. Architectural constraints
- Policy and delivery are separate; no adapter decides safety (ADR-007).
- Vela approves operations, not buttons; fail closed on any ambiguity.
- UI automation is opt-in and consent-gated (ADR-010).

## 7. Dependencies / blocked by
- K06 vela-uia delivery: single-use allow or refusal through patterns, never persistent options
- P03 Keep-awake thread and interactive-session probe
- R02 Startup reconciliation and recovery-resume
- H06 Decide whether v1 creates Desktop-hosted Antigravity sessions for approval delivery (UI Automation path scope)
- K02 Approval Watchdog and loop guard: progress heartbeats, thresholds, APPROVAL_STALLED

## 8. Expected write surfaces
- crates/vela-core/src/broker/session/**
- apps/desktop/src-tauri/src/wiring/approval.rs

## 9. Known shared contracts
- ApprovalSource and ApprovalDeliveryAdapter ports
- approval tables (requests, decisions, delivery attempts, fingerprints, policy rules)

## 10. Parallelization notes
After K06, K02, and the human decision H06 (whether v1 hosts Desktop-hosted Antigravity sessions); if H06 decides no, this ticket reduces to the headless pause semantics. Provisional until then: UI Automation is implemented and tested against the controlled fake approval window only; this never weakens ADR-020, FR-050, CAP-12, or AT-026.
