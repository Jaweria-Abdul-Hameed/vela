# F08: IPC gateway: command registry, snapshot plus sequenced event stream, resync

**Planned labels:** `type:feature` `area:orchestration` `risk:high` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 4 · **Direct blockers (published, transitively reduced):** F05, F06

> Symbolic key: `F08` · Area: orchestration · Phase: 0 · Risk: high

## 2. Objective
The renderer bootstraps from a snapshot, follows a sequenced event channel with coalescing, and recovers from reload or a gap by refetching.

## 3. Requirement IDs
FR-023, FR-048, NFR Performance

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Gateway in src-tauri: validated typed commands routed to the core by message; snapshot.get returning state plus last_seq; single event channel with coalescing to at most 30 emissions per second.
- Renderer client implementing bootstrap, gap detection, and resync.
- Contract test enforcing registry/wrapper parity.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

## 7. Dependencies / blocked by
- F05 Renderer skeleton: React, store, IPC wrappers, and front-end test tooling
- F06 Persistence foundation: single-writer SQLite, migration ladder, journal, and integrity checks

## 11. Acceptance criteria
- [ ] Reloading the renderer mid-stream results in a consistent store (test).
- [ ] A forced gap triggers a snapshot refetch; events burst at 1000/s are coalesced without losing journal entries.
- [ ] Unregistered commands and malformed arguments are rejected in the core.
