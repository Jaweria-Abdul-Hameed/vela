# O01: Orchestrator actor skeleton: message bus, transactional transitions, run creation, snapshot assembly

**Planned labels:** `type:feature` `area:orchestration` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 5 · **Direct blockers (published, transitively reduced):** D01, F08, F09, F07  
**Added by the Prompt 6 dependency audit** (not in the first draft).

> Symbolic key: `O01` · Area: orchestration · Phase: 1 · Risk: high

## 2. Objective
The Orchestrator owns run state: it receives typed messages, applies state-machine transitions as single transactions (state plus journal), creates runs, and assembles the snapshot served to the UI.

## 3. Requirement IDs
FR-019, FR-023, NFR Reliability

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Actor task with bounded message channels; run creation and the CREATED to PREFLIGHT to ANALYZING to GRAPH_READY driver hooks (implemented by later tickets); transition application through the D01 tables; journal append and post-commit publication; snapshot assembly for snapshot.get.
- Panic isolation for worker tasks (a worker panic fails that worker only).
- Owns the `workers` table migration (reserved block 0070-0079) and `wiring/orchestrator.rs`; every journal payload passes through the F07 Redactor before it reaches the writer thread; declares FaultPoints for transition application.
- Message routing and snapshot assembly are open-ended: each module registers a command handler (trait object) and a snapshot contributor through registries owned here, so adding a message or a snapshot part edits no shared enum or function (SHARED_SURFACE_PROTOCOL.md section 10).

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

## 11. Acceptance criteria
- [ ] An illegal transition is rejected and journaled; a legal one commits state and journal atomically (fault-point test); the snapshot reflects committed state only.
- [ ] Bounded channels apply backpressure and never drop a message; a panicking worker task does not take down the Orchestrator.
- [ ] A run can be created, persisted, and reloaded after restart.
- [ ] A seeded secret in an event payload is absent from the persisted journal row (test).
