# A05: Per-worker profile manager and generated settings and allow rules

**Planned labels:** `type:feature` `area:antigravity` `risk:high` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 5 · **Direct blockers (published, transitively reduced):** D05, SP08, TK1

> Symbolic key: `A05` · Area: antigravity · Phase: 2 · Risk: high

## 2. Objective
Each worker gets a Vela-owned profile with generated allow rules from the confirmed command profile, subject to the conversation-visibility spike result.

## 3. Requirement IDs
FR-038, FR-050

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Profile directory creation and lifecycle; generated permissions.allow entries (exact, regex) and a path-scoped write rule; environment redirection; no credential access; design adjusted to SP08 result (ADR-020).

## 6. Architectural constraints
- Only vela-adapters::antigravity and vela-uia may contain Antigravity-specific behavior (ADR-008, ADR-018).
- Never trust exit code or result.status; interpret events, stderr, and Git state.
- Never read, copy, or persist Antigravity credentials or tokens (ADR-016).
- Elements tagged [U] are gated by their spike; do not claim them ready.

## 7. Dependencies / blocked by
- D05 Policy engine core: operation model, PowerShell and cmd normalizer, ordered rules, ALLOW/ASK/DENY
- SP08 Spike S-DESKTOP-VISIBILITY: are headless CLI conversations visible and openable in Antigravity Desktop?
- TK1 Scripted fake agy executable replaying recorded Antigravity behavior

## 8. Expected write surfaces
- crates/vela-adapters/src/antigravity/profile/**

## 9. Known shared contracts

## 10. Parallelization notes
After SP08 records its result; do not start before it closes.

## 11. Acceptance criteria
- [ ] Generated rules allow only the confirmed command profile and the worker worktree path (verified against the fake and, gated, the real CLI).
- [ ] The profile never copies, reads, or references credentials.
- [ ] The design follows the SP08 result; if SP08 requires a different mechanism the ticket implements the approved alternative or raises a decision request.
- [ ] A worker profile directory is removed when its worker ends and never outlives the run.

## 12. Required unit tests
- Allow-rule generation from a command profile: exact, regex, and path-scoped write entries; no entry outside the confirmed profile (property test); environment redirection builds a per-worker `USERPROFILE`/`HOME`.
