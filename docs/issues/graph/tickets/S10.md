# S10: Worker lifecycle with a fake agent: provision, implement, focused validation, timeline

**Planned labels:** `type:feature` `area:orchestration` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 10 · **Direct blockers (published, transitively reduced):** S09, PV1, R01

> Symbolic key: `S10` · Area: orchestration · Phase: 1 · Risk: high

## 2. Objective
One ticket runs through provisioning, an implement turn on a fake agent, and focused validation, producing a persisted timeline.

## 3. Requirement IDs
FR-009, FR-011, FR-012, AT-001

## 4. User-visible behavior
None (data only; the timeline panel is U08).

## 5. Technical scope
- Worker task driving the AgentAdapter port; states PROVISIONING to FOCUSED_VALIDATION; validation commands via ProcessRunner; journal events; worker structured completion output.
- Registers worker-state reconciliation recipes.
- Owns the `ticket.inspect` and `timeline.get` read commands, reserved migration block 0090-0099 (`commands`, `test_runs`, worker conversation-id column), and the FaultPoints at every worker transition it implements; registers the worker-state recipe with R01.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

## 7. Dependencies / blocked by
- S09 Scheduler tick: frontier, safety, capacity, and worker records with a fake agent
- PV1 Worktree provisioning contract: confirmed commands, file allowlist, caches, resource keys
- R01 Operation records and idempotency framework

## 11. Acceptance criteria
- [ ] A scripted fake agent completes a ticket through provisioning, implement, and focused validation.
- [ ] Failing validation moves the worker to the FIXING path; exit code zero alone is never treated as success.
- [ ] Every transition is journaled with reason and evidence, and the conversation id reported by the adapter is recorded.
- [ ] The `ticket.inspect` and `timeline.get` commands return the persisted ticket state and timeline.

## 12. Required unit tests
- Worker transition table driven by scripted outcomes: success, failing validation, agent failure, timeout; validation results are recorded with exit code but success is derived from agent result and Git state.
