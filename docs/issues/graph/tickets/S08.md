# S08: Graph approval and Build start: integration branch, integration worktree, base SHA

**Planned labels:** `type:feature` `area:orchestration` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 8 · **Direct blockers (published, transitively reduced):** S06, G02, S04

> Symbolic key: `S08` · Area: orchestration · Phase: 1 · Risk: high

## 2. Objective
The user approves the graph and presses Build; Vela records the base SHA, creates the integration branch and worktree, and enters RUNNING.

## 3. Requirement IDs
FR-008, FR-045

## 4. User-visible behavior
Build-ready view with the graph summary and a Build action (full view arrives with the project universe).

## 5. Technical scope
- Graph approval recorded in the snapshot; trust check; base selection with divergence acknowledgement; integration branch and worktree creation; run_base_sha; STARTING to RUNNING.
- Declares FaultPoints for branch creation, integration-worktree creation, and the STARTING to RUNNING transition (SHARED_SURFACE_PROTOCOL.md section 6); owns reserved migration block 0080-0089 (`worktrees`, run base-SHA and integration-branch columns); provides the minimal Build action that U11 later extends.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.

## 7. Dependencies / blocked by

- G02 Worktree manager: root policy, create, remove, lock, repair, slug and case safety, cleanup
- S04 Preflight engine end to end: repository, toolchain, trust, and Windows checks with severity table

## 11. Acceptance criteria
- [ ] Build is refused for untrusted repositories and for a BLOCK preflight.
- [ ] The base SHA, integration branch, and integration worktree are recorded in one transaction with the transition to RUNNING.
- [ ] A diverged local default branch requires an explicit acknowledgement of the recorded base.
- [ ] The Build action shows enabled, blocked-with-reason, and in-progress states.

## 12. Required unit tests
- Base selection decision table: no remote, remote equal, local ahead, behind, and diverged (acknowledgement required); Build refusal for untrusted or BLOCK preflight; STARTING to RUNNING only after the integration worktree exists; a repeated Build press is idempotent.

## 13. Required integration tests
