# W01: Production composition root: real adapter wiring and a fixture run in the real window

**Planned labels:** `type:feature` `area:foundation` `risk:high` `phase:2` `ready-for-agent`  
**Depth in the DAG:** 11 · **Direct blockers (published, transitively reduced):** S10, S17, P03, T04  
**Added by the Prompt 7 independent audit** (not in the Prompt 6 draft).

> Symbolic key: `W01` · Area: foundation · Phase: 2 · Risk: high

## 2. Objective
The installed application is assembled from the real adapters, and a fixture project runs a ticket end to end inside the real window with a scripted agent, proving the product is wired and not only its tests.

## 3. Requirement IDs
FR-012, NFR Reliability, NFR Security, NFR Testability

## 4. User-visible behavior
The real window imports a fixture project, shows its graph, and runs a ticket; no new visual design.

## 5. Technical scope
- Wire the concrete adapters into the composition root: ProcessRunner with tree kill, power and session probe, the GitAdapter capability implementations, the local and GitHub trackers, and the notifier. The approval pipeline (broker, watchdog, UI Automation source and delivery) is wired by K07 in `wiring/approval.rs`; until then the approval port resolves to an explicit unavailable adapter that reports a typed, journaled condition.
- The scripted agent is selectable only through the `test-agent` cargo feature and a launch option; it is absent from release builds and a CI check proves it.
- Expose the resolved `vela-hook` path through one function (development path in development, installed path when packaged) used by the Antigravity profile generator.
- A smoke test launches the built application against a fixture repository, imports it, builds the graph, and completes one ticket with the scripted agent.

## 6. Architectural constraints
- Concrete adapters are wired only in the composition root; vela-core never depends on them (IMPLEMENTATION_ARCHITECTURE.md section 3).
- A missing adapter yields a typed CAPABILITY_MISSING, never a silent fake or another provider (FR-037).
- No second process unless spike S-TRAY failed (ADR-017).
