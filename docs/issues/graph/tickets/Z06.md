## 5. Technical scope
- Execute RELEASE_CHECKLIST.md; independent whole-codebase review and security and performance evidence; changelog; release tag per repository policy.
- **Production release-signing gate.** Build the release through the production profile of `release.yml` (Z01) with the production material that H04 provisioned, and verify the two signatures separately, with evidence for each: (A) the **Windows Authenticode** signature on the installer and the bundled `vela-hook` passes `signtool verify /pa` and chains to the production publisher identity recorded in `docs/release/SIGNING.md`, and is not the development certificate; (B) the **Tauri updater** artifacts verify against the production updater public key recorded in `docs/release/SIGNING.md`, the shipped configuration embeds that key, and it is not the disposable test key. Any development or test signing material found in a release candidate, or an open H04, is a FAIL of this gate and the product is not release-ready.

## 11. Acceptance criteria
- [ ] A release validation report lists each item with evidence.
- [ ] The product is not called release-ready unless every item passes.
- [ ] The release validation report records, separately, the Authenticode verification of the production-signed installer and `vela-hook` and the updater-signature verification against the production public key, each tied to the identifiers recorded by H04, and shows that no development certificate and no test updater key is present in the release candidate (FR-047 release evidence).
- [ ] The gate fails if H04 is open, if production credentials are missing, or if the production updater private-key custody and backup are not documented.
- [ ] The full-product lifecycle checks that need the complete product are executed on the H05 clean environment with the production-signed build and recorded as evidence for AT-019 and AT-023 (the automated suites remain Z03's and the feature owners' tickets): tray and background operation with hide-on-close, reboot continuation of a real run per the `recovery_continuation` setting, notifications with the window closed for a human-required event, a failure, and completion, and uninstall terminating the running app and removing its tray icon. Any item the guest cannot support is recorded NOT VERIFIED with its reason.
- [ ] Production-signed clean-machine behavior is part of the release evidence: the production-signed installer is installed on the H05 clean environment, with the guest's Smart App Control and SmartScreen state recorded and the outcome noted, where the guest supports the relevant Windows security feature (an unsupported feature is recorded as not applicable, never as passed). The Z07 evidence set (install, first launch, upgrade, uninstall, reboot, WebView2 status) is complete and every NOT VERIFIED item in it appears in the report with its reason.
