# S09: Scheduler tick: frontier, safety, capacity, and worker records with a fake agent

> Symbolic key: `S09` · Area: orchestration · Phase: 1 · Risk: high

## 2. Objective
On each material event the Orchestrator reconciles, recomputes the ready frontier, applies safety and capacity, and creates worker records transactionally.

## 3. Requirement IDs
FR-008, AT-002, AT-003

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Scheduling cycle steps 1-8 of ORCHESTRATION_ENGINE.md; concurrency cap; serialization reasons recorded; integration-health gate.
- Capacity input reads a profile-availability service from the Orchestrator service registry (absent means available, until S16 registers one): no worker starts on a profile reported as blocked (for example `POLICY_BLOCKED`), and a blocked profile is recorded as the serialization reason.

## 6. Architectural constraints
- The Orchestrator is the only writer of orchestration state; each transition is one transaction (state plus journal) (ADR-002, ADR-017).
- Events reach the UI only after commit.
- Scheduler never assumes a UI is open.
