# G02: Worktree manager: root policy, create, remove, lock, repair, slug and case safety, cleanup

**Planned labels:** `type:feature` `area:git` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 5 · **Direct blockers (published, transitively reduced):** G01

> Symbolic key: `G02` · Area: git · Phase: 1 · Risk: high

## 2. Objective
Vela creates and cleans isolated worktrees under a managed root outside synced folders, safely on Windows.

## 3. Requirement IDs
FR-010, FR-044

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Managed root policy; branch and worktree naming with deterministic slug truncation and hash suffix; case-collision detection; add, remove, lock, prune, repair; bounded-retry cleanup that reports lock holders.
- Dedicated integration worktree per run.

## 6. Architectural constraints
- Shell out to the git binary under the verified hardened invocation (IMPLEMENTATION_ARCHITECTURE.md; no libgit2).
- Never force-push; never rebase pushed branches; never touch the primary checkout working tree, index, or branch (ADR-011).

## 7. Dependencies / blocked by
- G01 GitAdapter: hardened invocation, read operations, and hostile-config tests

## 8. Expected write surfaces
- crates/vela-git/src/worktree/**

## 9. Known shared contracts
- GitAdapter worktree capability trait (F02)
- Uses the G01 per-worktree operation lock

## 10. Parallelization notes
Parallel with G05.

## 11. Acceptance criteria
- [ ] Worktrees are created at the recorded SHA and the branch, path, and SHA are returned for recording.
- [ ] A worktree root under a synced folder is refused.
- [ ] Cleanup removes only clean worktrees under the Vela-managed root.
- [ ] Long and case-colliding names produce deterministic, unique, bounded branch and path names.
- [ ] A file-locked cleanup retries with bounded backoff and reports the holder instead of force-killing it.

## 12. Required unit tests
- Slug truncation and hash-suffix determinism; case-collision detection; managed-root policy decisions for OneDrive, Dropbox, Google Drive, and iCloud paths; cleanup eligibility (clean and managed only).

## 13. Required integration tests
- Windows path-length and file-lock tests.
