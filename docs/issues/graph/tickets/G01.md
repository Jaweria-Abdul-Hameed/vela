# G01: GitAdapter: hardened invocation, read operations, and hostile-config tests

**Planned labels:** `type:feature` `area:git` `risk:high` `phase:1` `ready-for-agent`  
**Depth in the DAG:** 4 · **Direct blockers (published, transitively reduced):** P01, F03

> Symbolic key: `G01` · Area: git · Phase: 1 · Risk: high

## 2. Objective
Vela inspects repositories through a hardened Git invocation that neutralizes repository-controlled code execution.

## 3. Requirement IDs
FR-043, NFR Security

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- Hardened argument set and environment; status, refs, rev-parse, diff, merge-base, log, worktree list.
- Hostile-config fixture tests (diff.external, textconv, filter drivers, fsmonitor, hooks).
- Owns the per-worktree operation lock module (`vela-git/src/lock/**`) that G02, G03, G04, and G05 use; owns the capability-trait layout: one implementation file per capability (read here; worktrees G02; checkpoints G03; merges G04; remote G05).
- Read-only remote reachability probe (`ls-remote` under the hardened invocation) for preflight; fetch and push remain G05.

## 6. Architectural constraints
- Shell out to the git binary under the verified hardened invocation (IMPLEMENTATION_ARCHITECTURE.md; no libgit2).
- Never force-push; never rebase pushed branches; never touch the primary checkout working tree, index, or branch (ADR-011).

## 7. Dependencies / blocked by
- P01 ProcessRunner: spawn, allowlisted environment, timeouts, streamed redacted output, cancel token
- F03 Test kit foundation: fixture repositories, fault-injection harness, and the synced-folder guard

## 8. Expected write surfaces
- crates/vela-git/src/**
- crates/vela-git/src/lock/**
- crates/vela-git/src/read/**

## 9. Known shared contracts
- GitAdapter capability traits (F02)
- Per-worktree operation lock (owned here)

## 10. Parallelization notes
Parallel with D tickets; foundation for all G tickets. G02, G03, G04, and G05 each add one implementation file and must not edit this ticket's files.

## 11. Acceptance criteria
- [ ] The hostile repository executes no marker under any read operation.
- [ ] Operations report typed errors; Git version is recorded.
- [ ] Two holders of the same worktree lock are serialized; a different worktree is not blocked (test).
