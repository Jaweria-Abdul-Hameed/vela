## 5. Technical scope
- Verifies that the matrix covers every FaultPoint declared by S08, S10, S11, S12, S13, S14, R08, G03, G05, K01, and R01 (a completeness test fails when a declared point is missing); does not retrofit points into other tickets' code. R03 owns every matrix entry; the tickets that declare points never write into the matrix directories.
- Restart verification of refs, worktrees, state, journal, child processes, and remote state; a regression test for every failure found.
- The completeness test is a standing test that fails when any declared FaultPoint lacks a matrix entry. S13, S14, and R08 declare and place their own points and unit-test them with the F03 harness; R03 depends on all three so that it can add their matrix entries (Prompt 8 scheduler dry-run correction: previously nothing owned those entries); Z03 runs the completeness test last.

## 6. Architectural constraints

- Never replay a stale UI click.
