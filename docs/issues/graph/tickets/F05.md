# F05: Renderer skeleton: React, store, IPC wrappers, and front-end test tooling

**Planned labels:** `type:feature` `area:ui` `risk:low` `phase:0` `ready-for-agent`  
**Depth in the DAG:** 3 · **Direct blockers (published, transitively reduced):** F04

> Symbolic key: `F05` · Area: ui · Phase: 0 · Risk: low

## 2. Objective
The renderer has its folder structure, a Zustand store with a reducer for event envelopes, typed IPC wrappers, and unit, interaction, and visual test tooling wired.

## 3. Requirement IDs
NFR Testability, FR-025

## 4. User-visible behavior
None (no user-visible behavior).

## 5. Technical scope
- apps/desktop/src structure (scenes, surfaces, state, ipc) and packages/ui skeleton; store with reducer applying EventEnvelope and snapshot replacement.
- Typed invoke/listen wrappers over packages/contracts; Vitest, Testing Library, and Playwright (software GL) configured with one example test each.
- packages/test-fixtures with a sample snapshot and event stream.
- Scenes and surfaces self-register through Vite `import.meta.glob`, so adding one never edits `app.tsx` or a registry file (SHARED_SURFACE_PROTOCOL.md section 7); `packages/test-fixtures` is organized as `streams/<surface>/`.

## 6. Architectural constraints
- DOM owns all text and controls; only packages/ui/src/canvas imports React Three Fiber/Three.js (ADR-019).
- Not a conventional dashboard: no permanent sidebar, dense card grids, gratuitous glass, or random neon.
- Animation is derived from events or interaction; never authoritative for state.
- Reduced-motion and keyboard behavior are implemented in the same ticket, not later.
