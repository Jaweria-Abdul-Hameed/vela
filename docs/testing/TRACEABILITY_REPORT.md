# Requirements traceability report (Z05)

Dated 2026-10-15, against `main` after the mega-ticket build (M01 to M31). Every functional requirement (FR) and acceptance test (AT) is
mapped to where it is implemented, how it is tested, and what evidence exists. **Nothing is marked VERIFIED without automated or recorded
evidence.** Findings are recorded as findings: no requirement was reworded to fit the code.

Legend. **VERIFIED**: automated tests run in CI (and, where stated, a real run). **PARTIAL**: part of the requirement is tested; the gap is named.
**NOT VERIFIED**: no evidence exists yet (a real environment, a person, or a decision is needed). **NOT IMPLEMENTED (decision)**: deliberately
not built, with the decision that says so.

"CI" means the repository's CI (Rust on Windows, TypeScript and Playwright, Security). "Local real" means a run on the owner's machine with the
real Antigravity, recorded in `docs/release/ANTIGRAVITY_RELEASE_GATE.md`.

## Audit findings (stubs, skips, disabled rules, documentation drift)

**Empty skeleton files that remain** (`Module skeleton (F01)` header): these are not bugs, but each is listed so none is mistaken for a feature.

- Behaviour lives elsewhere: `recovery/{reconcile,resume}` (in `recovery/mod.rs`), `stop/safe_points` (in `stop/mod.rs`),
  `analysis/{ingest,graph_build}` (in `analysis/mod.rs`), `merge_lane/conflict` (conflicts abort and escalate inside `merge_lane/mod.rs`),
  `adapters/antigravity/mod.rs`, `apps/desktop/src/surfaces/*` and `scenes/*` (the surfaces are components in `packages/ui` composed by `Console`),
  `wiring/{project,settings}`, `autostart`, `notify` (the Tauri plugins carry these), `vela-testkit::recovery_matrix` (the matrix lives in `tests/e2e/tests/crash_matrix.rs`).
- Deliberately empty: `vela-core::review` (ADR-023/024), `vela-uia::visual` (SP13 defers the visual tier), `adapters/notifier`.
- Not yet built: `ui canvas/effects` and `canvas/focus` (the effect map exists as data in `visuals.ts`; nothing plays it on live events).

**Skipped tests**: none (`#[ignore]`, `todo!`, `unimplemented!` and `.skip` are absent). Real-environment tests are gated by `VELA_REAL_ANTIGRAVITY=1` and say they were skipped.
**Disabled lint rules**: eight `#[allow(clippy::too_many_arguments)]` or similar, each at a constructor or a test helper with many explicit inputs; two `eslint-disable` lines (a hook-dependency note in `DotField`, a control-character regex in `safe-content`). None hides a defect.
**Documentation drift found**: the MEGA_PROGRESS wall-clock cells for M21 and M27 read "0 min" (the timing file was reused); `ACCEPTANCE_TESTS.md` still lists AT-004 as required although review is off by decision; `RECOVERY.md` describes startup reconciliation as always running, which is true only since M29. The requirements were not edited.

**Wiring gaps found by this audit** (each is a real finding, not a documentation point): the approval watchdog loop, the interactive-session poll,
the Antigravity drift guard at turn boundaries, the sleep/wake re-checks, and a failed-open store recovery (`recover_store` and the Git inventory) are
implemented and tested as units but not started or called by the composition root. They are the first items of the next build.
