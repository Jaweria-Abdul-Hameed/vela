# D01 Decision Requests

Interpretations D01 had to make where `ORCHESTRATION_ENGINE.md` and `DOMAIN_MODEL.md` are silent or inconsistent. None changes product behavior beyond the conservative reading (reject what is not listed). Each is isolated in one place in `crates/vela-domain/src/state/` so a decision changes one rule. None is blocking.

| ID | Question | What D01 implemented | Where |
|---|---|---|---|
| DR-D01-1 | The diagram in section 1 draws `FINAL_FIXING` to `FINAL_VALIDATION` (`FINAL_REVIEW ⇄ FINAL_FIXING ⇄ FINAL_VALIDATION`) but the normative table 1.1 lists only `FINAL_FIXING` to `FINAL_REVIEW`. | The table wins: `FINAL_FIXING` to `FINAL_VALIDATION` is rejected. Likewise no direct `PAUSED`/`NEEDS_HUMAN` entry from `FINAL_*`, `CREATED`..`GRAPH_READY`..`AWAITING_START` except via `STOPPING` (Stop All), because the table lists direct entry only from `RUNNING`, `ANALYZING` (`GRAPH_INVALID`) and `STARTING`. | `run.rs` `PHASE_EDGES`, `Run::transition` |
| DR-D01-2 | Which `NEEDS_HUMAN` kinds are valid at run level? Section 3.2 says only `PROVIDER_POLICY_BLOCK` is "valid at worker and run level"; section 1.1 and 1.2 additionally name `GRAPH_INVALID`, `INTEGRATION_UNKNOWN`, `INTEGRATION_UNHEALTHY` as run-level kinds that are absent from the 3.2 table. | `InterventionKind` has 16 kinds: the 13 of 3.2 plus those 3. A worker accepts exactly the 13; a run accepts all 16 (no restriction invented). `GRAPH_INVALID` is required for `ANALYZING` to `NEEDS_HUMAN` and is rejected from every other origin. Section 3.2 should list the three run-level kinds. | `common.rs`, `run.rs` |
| DR-D01-3 | "No transition leaves `PROVIDER_POLICY_BLOCK` automatically; the only exits are resolve to `resume_state` or cancel" conflicts with "any non-terminal to `FAILED`" and "any non-terminal to `STOPPING`". | The acceptance criterion wins: from a held `PROVIDER_POLICY_BLOCK` (worker and run) only `Active(resume_state)` with `Cause::UserDecision` and `CANCELLED` are accepted; `FAILED` and `STOPPING` are rejected with `ProviderPolicyBlockHeld`. A block can still be entered from `STOPPING`. If an unrecoverable internal error must be able to fail a blocked run, that needs an explicit decision. | `run.rs`, `worker.rs` |
| DR-D01-4 | The `PAUSED` reason and the `NEEDS_HUMAN` kind per edge (for example which reason `RUNNING` to `PAUSED` may carry; the kind of `STARTING` to `NEEDS_HUMAN`). | Not constrained beyond the explicit rules above: any `PausedReason` and any kind is accepted on the listed edges. Worker `PAUSED`/`NEEDS_HUMAN` to each other, and run `PAUSED` to `NEEDS_HUMAN` (and back) without `STOPPING`, are not in the tables and are rejected. | `run.rs`, `worker.rs` |
| DR-D01-5 | Which worker states are "agent-driven" (so `WAITING_APPROVAL` can overlay them)? | `CONTEXT_LOADING`, `IMPLEMENTING`, `REVIEWING`, `FIXING`, `CONFLICT_RESOLUTION`. Not `PROVISIONING`, the validation states, `CHECKPOINTING`, the merge-lane states or exceptional/terminal states. While the overlay is active only the exceptional states are reachable (it never advances the worker; `ASK` becomes `NEEDS_HUMAN(APPROVAL_ASK)` with the prior state as `resume_state`). | `worker.rs` `is_agent_driven`, `WorkerStatus` |
| DR-D01-6 | Ticket projection when all blockers are `DONE` but integration is not healthy or the ticket is not eligible; and a `REVIEW_STALLED` blocker (the table lists only `FAILED`, `NEEDS_HUMAN`, `CANCELLED`). | Not healthy or not eligible: `PENDING`. A blocker in `REVIEW_STALLED` (a `NEEDS_HUMAN` kind) counts as stuck, so the dependent is `BLOCKED`. A `PAUSED` or `RATE_LIMITED` blocker is not stuck (`PENDING`). | `projection.rs` `project_unstarted` |
| DR-D01-7 | Failure loops inside the worker (focused validation failing, integration validation failing). Section 3 draws only the forward path and the review/fix loop. | Not invented: `FOCUSED_VALIDATION` and `INTEGRATION_VALIDATION` have no failure edge back to implementing/fixing (a failure is a worker `FAILED` or `NEEDS_HUMAN(INTEGRATION_REGRESSION)`). If the Orchestrator needs a retry edge it must be added to the specification. | `worker.rs` `PHASE_EDGES` |
| DR-D01-8 | `STOPPING` to `STOPPING`, and `STOPPING` to `CANCELLED`. | Rejected (not in the table; "any non-terminal to `STOPPING`" read as applying once). Cancel needs `PAUSED`/`NEEDS_HUMAN` first. The `FAILED` reason is recorded outside the machine. | `run.rs` |
